# Propose a change

> How-to · [Documentation](../../README.md#documentation)

Change `main` through a pull request that passes the merge check. What the
check runs: [Merge checks](../reference/merge-checks.md).

1. Branch from an up-to-date `main`:

   ```sh
   git switch main && git pull --ff-only && git switch -c my-change
   ```

2. Make the change. Files generated from `applications/` or
   `clusters/<name>/ci/` (keys, Secrets, namespace lists) are made by the
   merge check and committed to your branch; pull before pushing again. To
   make them yourself: `python3 tools/teams.py generate`, `python3 tools/ci.py generate`.

3. Optionally, run the layout checks locally; they are the first steps of the
   merge check:

   ```sh
   python3 tools/teams.py check && python3 tools/ci.py check && python3 tools/generated.py check
   ```

   Before the generated files are made, they fail with "is not current" for
   those files: expected, the merge check makes them. Kustomize and Helm
   errors (a missing file, a value a chart refuses) show only in the merge
   check's render.

4. Push and open a pull request against `main`.
5. Read the report the check posts as a comment: errors block the merge; the
   per-resource diff shows what will change on the cluster.
6. Merge once the status `Pipelines as Code CI / gitops-check` is green and the
   branch is up to date with `main` (rebase if `main` moved).
7. Check: the affected Applications are Synced and Healthy in Argo CD
   (`kubectl -n argocd get applications`).

To run the check again without a new commit, comment `/retest` on the pull
request.

Don't edit files marked `Generated by deploy-talos.py`: change the cluster
file and run deploy-talos.py instead (talos-install).
