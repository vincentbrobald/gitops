# Repository layout

> Reference · [Documentation](../../README.md#documentation)

What lives where in this repository. Why it is organized this way:
[Architecture](../explanation/architecture.md).

```
base/                         shared, hand-written content (no cluster names)
  tekton/pipelines/           Tekton Pipelines release (the upstream file, unchanged)
  tekton/pipelines-as-code/   Pipelines-as-Code release (unchanged) and this site's settings
  tekton/dashboard/           Tekton Dashboard release (read-only; unchanged)
  argocd-preview/             the render-only Argo CD's shared part (ksops stand-in)
  site-ca/                    the site's root CA, the one file (trust-manager's source)
  organization/               chart: a Forgejo organization and its owners
  team/                       chart: the platform's part of a team (components core, ci, packages),
                              and argocd-values.yaml for the teams' Argo CDs
  team-namespace/             kustomize base of every environment namespace;
                              sizes/medium, sizes/large: quota components
  ci-repository/              chart: a platform CI repository
  team-policies/              ClusterRole team-deployer, admission policies team-routes,
                              team-listeners, forgejo-users, team-forgejo
  namespace-cleanup/          CronJob deleting namespaces whose owning Applications are gone,
                              once Crossplane is done in them (opt-in by label)
applications/                 organizations, teams and their namespaces
  .sops.yaml                  who the teams' Secrets are encrypted for
  <org>/organization.yaml     a Forgejo organization and its Keycloak realm
  <org>/<team>/team.yaml      a team: members, repositories
  <org>/<team>/argocd/        generated by tools/teams.py
  <org>/<team>/<ns>/base/     the base of a namespace, shared by its environments
  <org>/<team>/<ns>/env/<env>/  an environment: an overlay of ../../base
clusters/<name>/              one folder per cluster
  .sops.yaml                  who the cluster's Secrets are encrypted for
  addons/                     Applications and ApplicationSets synced by the app-of-apps 'addons'
  addons/teams.yaml           the ApplicationSets that iterate applications/
  addons/ci.yaml              the ApplicationSet that iterates ci/
  addons/projects/            the AppProjects; tenants.yaml generated by tools/teams.py
  addons/generated/           generated by deploy-talos.py: the add-ons' Applications, the app-of-apps itself
  generated/<topic>/          generated by deploy-talos.py: manifests and SOPS Secrets by topic
  generated/CHECKSUMS         what deploy-talos.py wrote (tools/generated.py compares)
  crossplane/                 Crossplane's providers, their credentials, the activation policy
  ci/<name>/                  a platform CI repository: repository.yaml, its Secrets
  trust/                      the site CA's source and trust-manager's Bundle
  registries/harbor/          Harbor's settings through Crossplane (Application harbor)
  registries/artifact-keeper/ Artifact Keeper's settings through Crossplane (Application artifact-keeper)
  tekton/...                  overlays of base/: cluster-specific values and Secrets
  argocd-preview/             the render-only Argo CD's overlay: ksops stand-in, repository credentials
samples/                      examples, rendered by the checks, never deployed
  applicationsets/            one ApplicationSet per generator: list, git directories,
                              git files, clusters, matrix
  apps/, helm-releases/       what the sample sets generate Applications from
tools/teams.py                 checks applications/, generates its files
tools/ci.py                    checks clusters/<name>/ci/, generates its files and Secrets
tools/generated.py             checks deploy-talos.py's files against generated/CHECKSUMS
.gitops-check.yaml            entry points and settings of the merge-request checks
docs/                         this documentation; docs/diagrams.py draws its SVGs
.tekton/pr-check.yaml         the merge-request checks' PipelineRun (read from main only)
```

## Per cluster or once per site

| In `clusters/<name>/` | On every cluster | Only on `lab` |
|---|---|---|
| `addons/generated/`, `generated/`, `.sops.yaml` (deploy-talos.py) | yes | |
| `addons/projects/` | `default`, `platform-infra`, `platform-services` | `preview`, `tenants` |
| `addons/trust-manager.yaml`, `trust/` | yes | |
| `addons/crossplane*.yaml`, `crossplane/`, `registries/`, `addons/harbor.yaml`, `addons/artifact-keeper.yaml` | | yes: Crossplane manages site objects |
| `addons/teams.yaml`, `addons/team-policies.yaml`, `addons/namespace-cleanup.yaml`, `applications/` | | yes: the teams |
| `addons/ci.yaml`, `ci/`, `tekton/`, `addons/tekton-*.yaml`, `addons/pipelines-as-code.yaml` | | yes: the site's CI |
| `addons/argocd-preview.yaml`, `argocd-preview/` | | yes: the merge checks |

Why: [Several clusters](../explanation/several-clusters.md). How:
[Add a cluster](../how-to/add-a-cluster.md).

## Who writes what

| Files | Written by |
|---|---|
| starting with `# Generated by deploy-talos.py` (`addons/generated/`, `generated/`) | `deploy-talos.py` (talos-install), from the cluster file `/root/lab/<name>.yaml`; pushed to `main` directly |
| starting with `# Generated by tools/teams.py` or `tools/ci.py` | those scripts ([tools](tools.md)) |
| everything else | by hand, through pull requests |
